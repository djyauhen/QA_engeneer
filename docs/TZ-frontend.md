# ТЗ: внутренний помощник QA — frontend

| | |
|---|---|
| Источник | `docs/TZ.md`, версия 1.6 |
| Статус | Draft |
| Дата | 2026-10-07 |
| Аудитория | Frontend-разработчик MVP |

Документ описывает поведение клиента. Клиент MVP — Angular 21. Это решение реализации, не новое правило проверок.

Экраны те же, что в задании дизайнера. Здесь — что запрашивать, что рисовать и чего не рисовать.

Имена методов — предлагаемый контракт из `docs/TZ-backend.md`. Исходное ТЗ эти пути не фиксирует. Если путь в коде назовут иначе, смысл метода сохранить. Бизнес-правила при расхождении брать из `docs/TZ.md` версии 1.6, не из удобства клиента.

Язык интерфейса и текстов отчёта — русский. Текст ленда и цитаты не переводить.

---

## Назначение MVP

Внутренний инструмент до 10 человек. Пользователь выбирает ленд в таблице каталога или вводит `human_id`. Система скачивает `original`, гоняет статику, поднимает изолированный просмотр, вызывает ИИ и Lighthouse, показывает отчёт.

Отчёт рекомендательный. Общего вердикта «годен / не годен» нет. Клиент такой бейдж не рисует и не вычисляет его из `passed` / `warning` / `failed` и баллов Lighthouse.

## Роли

Первого ТЛ задаёт окружение. Остальных создаёт ТЛ в продукте. Это не учётки AIO. Отдельной формы входа в AIO нет. Токен AIO клиент не вводит, не хранит и не логирует.

| Роль | Клиент |
|------|--------|
| ТЛ | Все проверки, все отчёты, экран затрат, экран конфига, экран «Пользователи», экран «Каталог AIO» |
| QA | Полный набор проверок, только свои отчёты. Методы затрат, конфига, пользователей и запроса каталога AIO не вызывать. Эти пункты меню не показывать |

Роль брать из `GET /session` после `POST /session`. Тело входа: `{ "login", "password" }`. Не доверять спрятанной кнопке как единственной защите: сервер всё равно откажет. Клиент при отказе не подставляет пустой чужой список, не подставляет нулевые затраты и не подставляет пустой список пользователей.

## Что не входит в MVP

- Общий статус проверки и автоматический блок ленда.
- Отдельный логин каждого QA в AIO.
- Анализ архива `merged` и переключатель `merged` / `original`.
- Исходящие интеграции: Jira, Telegram, почта, таблицы.
- Отдельное скрытие персональных данных на ленде.
- История изменений админ-конфига.
- Фиксированный суточный объём проверок.
- Золотой набор эталонных лендов.
- Саморегистрация.
- Восстановление пароля и самостоятельная смена пароля.
- Удаление и редактирование пользователей.

## Методы, на которые опирается клиент

| Действие пользователя | Метод |
|-----------------------|--------|
| Войти | `POST /session` |
| Узнать роль | `GET /session` |
| Выйти | `DELETE /session` |
| Показать таблицу каталога | `GET /catalog`. Ответ: `{ items, refreshed_at, query }` |
| Обновить каталог сразу | `POST /catalog/refresh`. Тот же ответ. В AIO уходит сохранённый запрос |
| Прочитать запрос каталога AIO | `GET /admin/catalog-query`. Только ТЛ |
| Сохранить запрос каталога AIO | `PUT /admin/catalog-query`. Только ТЛ. В AIO этот метод не ходит |
| Запустить проверку | `POST /checks` с `{ "human_id": "<строка>" }` или, если выбрана строка, `{ "human_id": "<строка>", "uuid": "<UUID>" }` |
| Ход и готовые блоки | `GET /checks/{check_id}` |
| Разрешить или не разрешать ИИ | `POST /checks/{check_id}/ai-decision` с `{ "decision": "allow" }` или `{ "decision": "deny" }` |
| Разрешить действия ленда на стенде | `POST /checks/{check_id}/stand-actions` с `{ "decision": "allow" }` |
| Список отчётов | `GET /reports` |
| Открыть отчёт | `GET /reports/{report_id}` |
| Прошлый отчёт того же `human_id` | `GET /reports/{report_id}/previous` |
| Прочитать конфиг | `GET /admin/rules` |
| Сохранить конфиг | `PUT /admin/rules` |
| Затраты | `GET /admin/costs` |
| Список пользователей | `GET /admin/users` |
| Создать пользователя | `POST /admin/users` с `{ "login", "password", "role" }`. `role`: `ТЛ` или `QA` |

`POST /session`: тело `{ "login", "password" }`. Пароль в лог, телеметрию и хранилище браузера не писать.

## Экраны и поведение

### Вход

До сессии показать вход в помощник. Поля: «Логин» и «Пароль». `POST /session` с телом `{ "login", "password" }`. После `GET /session` оболочка зависит от роли.

Ошибка входа: «Неверный логин или пароль.» Не показывать, какое из двух неверно. Восстановление пароля и смену пароля не рисовать. Саморегистрации нет.

Пароль не логировать.

QA не строит маршруты затрат, конфига, пользователей и каталога AIO. ТЛ строит.

### Запуск проверки

Таблица из `GET /catalog`. Колонки ровно три, в этом порядке: `human_id` с заголовком «id», `name` с заголовком «Лендинг», `created_at` с заголовком «Создано». Других колонок нет. `uuid` в колонку не выводить: он нужен только для запуска выбранной строки. Порядок ответа не пересортировывать. Пустой `created_at` — пустая ячейка, строку не скрывать. «Создано» показывать читаемо: день, месяц, год и время, как значение пришло в строке, без своего правила часового пояса.

Поле «Поиск» фильтрует уже показанную таблицу по подстроке в `human_id` или `name`, без учёта регистра. Пустое поле — вся таблица. Поиск не вызывает AIO, `GET /catalog` и `POST /catalog/refresh` и не подменяет каталог. Пустая таблица каталога и пустой результат поиска — разные состояния: «В каталоге нет лендов.» и «Ничего не найдено.»

Кнопка «Обновить» сразу вызывает `POST /catalog/refresh` и показывает `items` из этого ответа. В AIO уходит запрос, сохранённый на экране «Каталог AIO». Отдельный `GET /catalog` после кнопки не нужен. Таймер 10 минут на клиенте не подменяет эту кнопку. Десять минут — фон сервера.

Под заголовком короткая строка, откуда список. Пустой `query` (`search` равен `""`, `filters` пустой, `dates` равен `null`): «Последние 300 лендов AIO». Иначе непустые части: поиск, режимы, период. Если `refreshed_at` есть — «Обновлено …», тем же правилом, что «Создано»: как значение пришло, без сдвига пояса. Поиск по уже загруженной таблице это не меняет.

Клик по строке выбирает её. «Запустить проверку» по выбранной строке вызывает `POST /checks` с `human_id` и `uuid` этой строки.

Поле ввода `human_id` остаётся отдельно от поиска. Пример формата в подсказке: `359226`. Это запуск без `uuid`. Клиент не обрезает строку до числа. Если введённая строка точно равна одному `human_id` в ответе `GET /catalog`, `POST /checks` уходит только с `human_id`. Если точно равна нескольким — коллизия на экране, `POST /checks` не слать и `uuid` сам не подставлять: человек выбирает строку. Если ни одному — `POST /checks` только с `human_id`. Текст «не среди последних 300» показать, когда так ответил сервер: до этого ответа сервер делает один дозапрос кэша. Если после дозапроса сервер нашёл одну строку, проверка идёт дальше. Если нашёл несколько — коллизия, скачивание не начинать.

Пока сервер не подтвердил одну строку, не показывать шаги скачивания.

Карточка до скачивания остаётся после выбора строки или после того, как текстом нашлась одна строка. Таблица её не заменяет. Поля, если сервер их отдал:

| Поле | Показ |
|------|--------|
| `name` | Название |
| `human_id` | Как в выбранной строке или как ввели |
| `countries` | Список или пусто |
| `languages` | Список или пусто |
| `lander_type.name` | Тип. Пример значения в подсказке: `Preland w/ Form` |
| `status` | Подпись: «Статус в каталоге. Это не вердикт проверки.» |
| `preview_image` | Только здесь, как контекст. Подпись: «Превью каталога. Это не скриншот стенда.» В постоянный отчёт не копировать |
| `mvt_settings` | Как контекст вариантов. В чеклист правил не превращать |

`uuid` показывать не обязательно.

Если `POST /checks` вернул `replaced_previous_stand: true`, показать: «Предыдущий просмотр этого пользователя заменён.» Чужой просмотр не упоминать и не обновлять.

### Нет в каталоге и коллизия

Ответ «нет среди последних 300»: текст «Этого human_id нет среди последних 300 лендов. Скачивание не начато.» Ход проверки не открывать.

Коллизия текстового запуска: текст «Несколько записей с одним human_id. Выбор не делается. Скачивание не начато.» Отдельного переключателя строк нет. Человек выбирает строку в таблице, и следующий `POST /checks` уходит с `human_id` и `uuid` этой строки. Без выбранной строки тот же `human_id` снова не слать как выбор победителя. Если сервер ответил, что пара `human_id` и `uuid` не совпала со строкой кэша, ход проверки не открывать.

### Ход проверки

Опрос `GET /checks/{check_id}`, пока проверка не дошла до отчёта или до ошибки части, после которой продолжать нечего.

Шаги, которые сервер может прислать: `catalog`, `download_request`, `notifications`, `download_file`, `unpack`, `static`, `ai_gate`, `stand`, `ai`, `lighthouse`, `report`.

Состояния шага: `pending`, `running`, `retrying`, `waiting_user`, `done`, `failed`, `skipped`.

| Состояние | Текст |
|-----------|--------|
| `running` | Имя шага |
| `retrying` | «Идёт повтор» |
| `failed` | «Ошибка этой части» и имя шага |
| `waiting_user` | Развилка ИИ |

Подписи шагов на русском: поиск в каталоге, запрос скачивания, ожидание уведомления, скачивание архива, распаковка, статические проверки, решение по ИИ, стенд, ИИ, Lighthouse, отчёт.

`ai` и `lighthouse` могут быть активны вместе. Не блокировать отрисовку ИИ ожиданием Lighthouse.

Уже пришедший успешный блок оставлять на экране, если соседний шаг `failed`.

Слова «ленд плохой» не использовать.

Ветка отказа от ИИ: стенд и Lighthouse не помечать запущенными, пока сервер сам не прислал эти шаги. Исходное ТЗ не закрывает, стартуют ли они после `deny`.

### Развилка ИИ

Показывать только если сводка статики — «есть failed» и шаг `ai_gate` в `waiting_user`.

Кнопки:

- «Разрешить ИИ» → `ai-decision` `allow`
- «Не разрешать ИИ» → `ai-decision` `deny`

Текст: «Есть критичные находки статики (failed). ИИ сам не стартовал.»

Если сводка «только warning» или «все passed», кнопки не показывать и `ai-decision` не вызывать.

Если структура `failed`, рисовать только пункты, которые есть в ответе. Не создавать остальные 19 строк со статусом `failed`. Текст: «Проверка структуры не пройдена. Остальные статические пункты не запускались.»

Пункт статики: имя, `passed` / `warning` / `failed`, текст находки, путь, если путь есть.

### Отчёт

`GET /reports/{report_id}`. Одна страница, три блока: Статика, ИИ, Lighthouse.

Шапка: название, `human_id`, страны, языки, тип, статус каталога, дата отчёта. Строка: «Отчёт рекомендательный. Решение принимаете вы.»

Не рендерить поля `overall_status` и `verdict`, даже если они ошибочно появятся в ответе. Не считать их на клиенте.

| Блок | Статусы, которые показывать как пришли |
|------|----------------------------------------|
| Статика | «есть failed», «только warning», «все passed», «проверка не завершилась» |
| ИИ | «Список готов», «не запускался (ждут решения пользователя)», «ошибка после повторов» |
| Lighthouse | «Выполнен», «Ошибка прогона» |

Ошибка ИИ не скрывает статику. Ошибка Lighthouse не скрывает статику и ИИ.

Имена пунктов статики — как в отчёте сервера. Клиент не ведёт второй список правил и не помечает отсутствующий пункт провалом.

Находка ИИ на экране только если есть путь, цитата и скриншот. Иначе карточку не строить. Пустой список при «Список готов» не превращать в «годен».

Lighthouse: две группы, mobile и desktop. Метрики: performance score, First Contentful Paint, Largest Contentful Paint, Total Blocking Time, Cumulative Layout Shift, Speed Index, Time to Interactive. Порога, цвета «хорошо/плохо» по баллу и accessibility нет.

Подписанный URL и временный URL стенда в этом представлении не выводить. `preview_image` в постоянный отчёт не подставлять с карточки запуска.

### Сравнение

Рядом текущий отчёт и ответ `GET /reports/{report_id}/previous`.

Общий вердикт, «лучше», «хуже», «регресс» не считать и не рисовать. Даже если у пунктов разные статусы, клиент не сводит их в один знак.

Пустой прошлый отчёт: «Прошлого отчёта этого human_id нет.»

QA не запрашивает предыдущий отчёт чужого `report_id`. ТЛ открывает отчёт в пределах `GET /reports`.

### Стенд

Пока в `GET /checks/{check_id}` есть `stand_url`, показать его на экране стенда и подпись: «Временный адрес. В отчёт он не сохраняется.»

В консоль, аналитику и постоянный отчёт этот URL не писать.

До `stand-actions` показать: «Ленд сам ничего не выполняет: нет отправки лидов и нет сторонних пикселей.» Кнопка «Разрешить действия ленда» один раз вызывает `{ "decision": "allow" }`. Самим этот метод при открытии экрана не вызывать.

Исходное ТЗ называет разрешение действием QA. Для роли ТЛ вопрос открыт: кнопку не нажимать автоматически. Если сервер отказал ТЛ, показать отказ, не обходить его повторной отправкой.

Если `stand_url` нет, не подставлять ссылку из отчёта. Отдельный текст «среда не выдала URL» исходным ТЗ не задан.

### Списки отчётов

`GET /reports`.

QA: не добавлять фильтр по другому пользователю и не рисовать чужие строки, даже если они попали в ответ. Такой ответ считать сбоем доступа, список не показывать.

ТЛ: все строки, которые отдал сервер. Колонка «кто запустил», если сервер её отдал.

В строке: дата, `human_id`, название, три статуса частей. Общей колонки годности нет.

Срок 3 месяца клиент не отсчитывает. Дату показывает.

### Затраты, только ТЛ

`GET /admin/costs`.

Если `usage_reported` ложен или учёта в ответе нет: «Провайдер модели не вернул учёт использования.» Нули от себя не рисовать.

Если цифры есть, показать их без тарифа, валюты продукта и пересчёта. Схема полей провайдера не задана: неизвестные ключи показать как пришли, новые бизнес-поля не выводить формулой.

QA метод не вызывает.

### Конфиг, только ТЛ

`GET /admin/rules` и `PUT /admin/rules`. Историю не запрашивать и не рисовать: метода истории нет.

Поля, которые редактируются, и только они:

| Что на форме | Ключ контракта |
|--------------|----------------|
| Разрешённые внешние префиксы | `allowed_external_prefixes` |
| Запрещённые макросы | `forbidden_macros` |
| Запрещённые скриптовые признаки | `forbidden_script_markers` |
| Пороги изображений | `image_warning_kb`, `image_failed_kb` |
| Пороги CSS | `css_ok_kb`, `css_failed_kb` |
| Порог встроенного скрипта | `inline_script_max_nonempty_lines` |
| Флаг формы | `expectFormMacro` |
| Языки поверх метаданных | `languages_override` |

Кнопки «добавить новый тип проверки» нет. `expectFormMacro` не вычислять из `lander_type.name`. Подпись языков не должна обещать «замена» или «дополнение»: режим не задан. Текст рядом с конфигом: «История изменений не ведётся.»

Стартовые числа и префиксы показывает сервер. Клиент не хранит второй источник порогов.

QA метод не вызывает.

### Пользователи, только ТЛ

`GET /admin/users` и `POST /admin/users`.

Список: логин и роль. Пароля и хеша нет. Учётку, которую сервер пометил как заданную окружением, показать с пометкой «Задана окружением», без пароля. После создания пароль в списке не показывать и не оставлять на экране.

Форма: логин, пароль, роль `ТЛ` или `QA`. Ответ, что логин уже есть, включая совпадение с логином из окружения: «Такой логин уже есть.»

QA маршрут пользователей не строит и методы не вызывает. При отказе сервера список не показывать.

Удаление и редактирование не рисовать: таких методов нет. Восстановление пароля и смену пароля не рисовать.

### Каталог AIO, только ТЛ

Маршрут `/catalog-query`. Пункт меню «Каталог AIO» виден только ТЛ. QA маршрут не строит и `GET /admin/catalog-query`, `PUT /admin/catalog-query` не вызывает.

Форма задаёт запрос списка лендов в AIO. «Сохранить» — `PUT /admin/catalog-query`. Этот метод в AIO не ходит. Список на экране запуска меняется после «Обновить»: `POST /catalog/refresh` применяет уже сохранённый запрос и отдаёт `items`, `query`, `refreshed_at`.

| Поле | Что уходит |
|------|------------|
| Поиск AIO | `search`, одна необязательная строка. Это поиск на стороне AIO, не фильтр уже показанной таблицы |
| Режим (mode) | Значения через запятую, например `Editor`. Пусто — `filters: []`. Иначе один фильтр `{ "key": "mode", "operator": "in", "value": ["…"] }` |
| Период | Два поля даты-времени и пояс. Все три пустые — `dates: null`. Иначе три строки: `YYYY-MM-DD HH:mm:ss`, `YYYY-MM-DD HH:mm:ss`, пояс. Время в дате не сдвигать: пояс уходит отдельной строкой. Пустой форме пояс по умолчанию не подставлять. Пример пояса: `Europe/Minsk` |

## Чего клиент не делает

- Не логирует токен AIO, пароль и подписанные URL. Не пишет их в отчёт, localStorage и телеметрию.
- Не показывает общий бейдж «годен / не годен».
- Не вызывает ИИ сам, минуя сервер. Не вызывает `ai-decision`, если `failed` нет.
- Не вызывает `stand-actions` без нажатия.
- Не прячет успешный блок из-за ошибки другого блока.
- Не рисует затраты, конфиг, пользователей и каталог AIO роли QA.
- Не запрашивает чужие отчёты ролью QA.
- Не предлагает Jira, Telegram, почту.
- Не рисует порог Lighthouse.
- Не пересортировывает строки `GET /catalog`.
- Не ходит поиском в AIO и не подменяет им каталог.

Один развёрнутый ленд на пользователя обеспечивает сервер. Клиент только показывает замену своего просмотра.

## Вне объёма

Вёрстка бренда, реализация правил SpyOwl, вызов AIO с токеном, расчёт тарифа, история конфига, золотой набор лендов. Клиент зафиксирован: Angular 21.

## Открытые вопросы

Те же дыры, что в исходном ТЗ. Клиент их не закрывает угадыванием.

| Вопрос | Поведение клиента до ответа |
|--------|-----------------------------|
| Стенд и Lighthouse после `deny` | Рисовать только те шаги, которые прислал сервер |
| Кнопка стенда у ТЛ | Не нажимать автоматически |
| Статус ИИ после отказа | Не ставить «годен». Не выдумывать четвёртый статус сверх ответа сервера |
| Языки: замена или дополнение | Редактировать поле, режим не подписывать |
| Схема затрат | Показать пришедшее или «учёта нет» |
| Имена маршрутов | Смысл таблицы методов важнее буквального пути |
| Пороги Lighthouse | Не вводить |

Закрыто исходным ТЗ: поля `POST /session` — `login` и `password`. Ошибка входа одна: «Неверный логин или пароль.»

## Критерии приёмки

Принимает заказчик. Золотого набора лендов нет. Пороги баллов Lighthouse в приёмку не входят.

| # | Готово, если |
|---|----------------|
| 1 | Под ролью QA нет чужих отчётов, затрат, конфига и каталога AIO, и клиент эти методы не вызывает. Под ролью ТЛ есть все отчёты и экран затрат, включая «учёта нет». QA не строит маршруты пользователей и каталога AIO и эти методы не вызывает. ТЛ из окружения входит и может создать пользователя с ролью. Пароль после создания в списке не показан |
| 2 | Таблица экрана берётся из `GET /catalog`: три колонки, порядок ответа без своей сортировки, поиск фильтрует локально `human_id` и `name`. Выбор строки шлёт `POST /checks` с `human_id` и `uuid`. Ввод одного точного `human_id` шлёт `POST /checks` без `uuid`. Для ленда вне последних 300 и при коллизии без выбранной строки нет экрана скачивания. Кнопка «Обновить» вызывает `POST /catalog/refresh` сразу и применяет сохранённый запрос каталога |
| 3 | При битой структуре на экране только пришедшие пункты. Есть «Разрешить ИИ» и «Не разрешать ИИ». Без ответа ИИ не выглядит запущенным |
| 4 | Без `failed` диалога ИИ нет. Находка ИИ без пути, цитаты или скриншота не рисуется. Общего бейджа нет |
| 5 | На стенде есть временный URL, если сервер его прислал, и кнопка разрешения действий. До нажатия клиент не шлёт `stand-actions` |
| 6 | При `replaced_previous_stand` виден текст замены своего просмотра. Чужой просмотр клиент не трогает |
| 7 | Блок Lighthouse показывает mobile и desktop без вердикта по баллу. Ошибка Lighthouse не скрывает статику |
| 8 | Ошибка ИИ не скрывает статику |
| 9 | Интерфейс и отчёт по-русски. `GET /reports/{report_id}/previous` открывается рядом с текущим. Вердикт сравнения не рисуется. Дата отчёта видна |
| 10 | Клиент не логирует токен и подписанные URL и не кладёт их в постоянный отчёт |
| 11 | «Обновить» не ждёт 10 минут |
