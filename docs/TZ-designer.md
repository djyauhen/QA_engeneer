# ТЗ: внутренний помощник QA — дизайнер

| | |
|---|---|
| Источник | `docs/TZ.md`, версия 1.6 |
| Статус | Draft |
| Дата | 2026-10-07 |
| Аудитория | Дизайнер интерфейса MVP |

Документ самодостаточен для макетов. Вёрстку, сетку и API здесь не задаём. Клиент — Angular 21. Тексты интерфейса и отчёта — русские. Текст ленда может быть на любом языке: цитаты в отчёте не переводить.

Визуальный стиль бренда в исходном ТЗ не задан. Это внутренний рабочий инструмент. Новый бренд, логотип и маркетинговая обложка не нужны.

---

## Назначение MVP

Внутренний инструмент до 10 человек. Пользователь выбирает ленд в таблице каталога или вводит `human_id`. Система скачивает `original`, гоняет статику, поднимает изолированный просмотр, вызывает ИИ и Lighthouse, показывает отчёт.

Отчёт рекомендательный. Общего вердикта «годен / не годен» нет. Решение принимает человек.

## Роли

Первого ТЛ задаёт окружение. Остальных создаёт ТЛ в продукте. Это не учётки AIO. Отдельного входа в AIO на экранах нет.

| Роль | Что видит |
|------|-----------|
| ТЛ | Все проверки, все отчёты, статистика затрат на модели, админ-конфиг правил, экран «Пользователи» |
| QA | Полный набор проверок, только свои отчёты. Затрат нет. Конфиг не меняет и не видит. Пункта «Пользователи» нет |

## Что не входит в MVP

- Общий статус проверки и автоматический блок ленда.
- Отдельный логин каждого QA в AIO. Один сервисный токен, его на экранах нет.
- Анализ архива `merged`.
- Исходящие интеграции: Jira, Telegram, почта, таблицы.
- Отдельное скрытие персональных данных на ленде.
- История изменений админ-конфига.
- Фиксированный суточный объём проверок.
- Золотой набор эталонных лендов.
- Саморегистрация.
- Восстановление пароля и самостоятельная смена пароля.
- Удаление и редактирование пользователей.

## Термины на экранах

| Термин | Как показывать |
|--------|----------------|
| `human_id` | Колонка «id» в таблице и отдельное поле запуска. Пример формата: `359226` |
| `uuid` | В UI не обязателен. Карточка узнаётся без него |
| `original` | Архив, который система берёт в работу. Подпись в текстах: «Original upload», если нужна |
| `merged` | В MVP не скачивается. Отдельный экран выбора файла не рисовать |
| `passed` / `warning` / `failed` | Статусы пункта статики. Подписи можно оставить этими словами |
| Критичная находка | Пункт со статусом `failed` |
| ТЛ, QA | Роли помощника |
| `expectFormMacro` | Флаг в админ-конфиге. Стартовое значение `true` |
| Lighthouse | Отдельный блок метрик, без вердикта по баллу |
| Стенд | Изолированный просмотр с подставленными макросами |

`status` ленда из каталога — контекст строки, не вердикт помощника. `preview_image` — контекст карточки до скачивания, не замена скриншота стенда. `mvt_settings` — контекст вариантов, не правила проверки.

## 1. Вход

Экран входа в помощник. Поля: «Логин» и «Пароль». Кнопка «Войти». После входа видна роль: ТЛ или QA.

Не рисовать логин AIO, поле токена, cookie, tenant. Восстановление пароля и смену пароля не рисовать. Саморегистрации на этом экране нет.

Ошибка входа: «Неверный логин или пароль.» Не писать, что именно неверно. Отдельной блокировки и капчи нет.

## 2. Запуск проверки

Таблица каталога последних 300. Колонки ровно три, в этом порядке:

| Поле | Заголовок |
|------|-----------|
| `human_id` | id |
| `name` | Лендинг |
| `created_at` | Создано |

Других колонок нет. `uuid` в таблицу не выводить.

«Создано» показывать читаемо: день, месяц, год и время. Часовой пояс не пересчитывать и новое правило пояса не вводить: брать время как оно пришло в строке. Если `created_at` нет, ячейка пустая, строка на месте.

Порядок строк — по убыванию числового id: больший id сверху. Это не алфавитный порядок подписи.

Поле «Поиск» фильтрует уже показанную таблицу по подстроке в id или названии, без учёта регистра. Пустое поле — вся таблица. Поиск не выглядит как новый запрос каталога и не подменяет таблицу другим списком.

Кнопка «Обновить» на этом экране. Она запрашивает каталог сразу, не через 10 минут. Десять минут — фоновое поведение системы, на экране его не объяснять абзацем.

Пустая таблица и пустой результат поиска — разные состояния.

- Каталог без строк: «В каталоге нет лендов.» Не писать «ничего не найдено», если человек ничего не искал.
- Поле поиска непустое и ни одна строка не подошла: «Ничего не найдено.» Это фильтр показанной таблицы, не другой каталог.

Клик по строке выбирает её. Кнопка «Запустить проверку» запускает выбранную строку.

Поле ввода `human_id` остаётся отдельно от поиска. Подсказка формата: `359226`. Это запуск текстом, без выбранной строки. Сравнение — точная строка, не число для сортировки. Ровно одна строка с таким текстом — запуск этой строки. Несколько — коллизия, скачивание не начато, человек выбирает строку в таблице сам. Нет среди последних 300 — текст раздела 3, скачивания нет.

Кнопка запуска проверки. Пока строка не выбрана и текст не совпал с одной строкой, скачивание не показывать начатым.

Карточка до скачивания появляется после выбора строки или после того, как текстом нашлась одна строка. Таблица карточку не заменяет. Карточка остаётся до скачивания.

| Поле | Как подписать | Смысл на макете |
|------|----------------|-----------------|
| `name` | Название | Подпись ленда |
| `human_id` | human_id | Ключ выбранной строки или введённый текст |
| `countries` | Страны | Список, может быть пустым |
| `languages` | Языки | Список, может быть пустым |
| `lander_type.name` | Тип | Пример значения: `Preland w/ Form` |
| `status` | Статус в каталоге | Контекст строки. Не бейдж годности |
| `preview_image` | Превью каталога | Картинка контекста. Подпись, что это не скриншот стенда |
| `mvt_settings` | Варианты | Контекст. Не чеклист правил |

Пустое поле показывай пустым, проверку из-за пустого необязательного поля не останавливай на макете. `uuid` в карточку не обязателен.

`preview_image` на постоянной странице отчёта не дублировать как доказательство. Образец URL в макеты файлами не вставлять: плейсхолдер «превью каталога».

## 3. Ошибки до скачивания

**Нет среди последних 300.** Один текст, без шагов скачивания и без отчёта.

Текст: «Этого human_id нет среди последних 300 лендов. Скачивание не начато.»

**Коллизия.** Запуск только текстом `human_id`, без выбранной строки, и строк с этим id несколько. Отдельных радиокнопок нет: выбор — клик по строке таблицы, затем «Запустить проверку».

Текст: «Несколько записей с одним human_id. Выбор не делается. Скачивание не начато.»

## 4. Ход проверки

Шаги видны списком. Активен текущий. Уже готовый шаг остаётся отмеченным, даже если позже падает другая часть.

| Шаг на экране | Когда он бывает |
|---------------|-----------------|
| Поиск в каталоге | Всегда в начале запуска |
| Запрос скачивания | После найденной одной строки |
| Ожидание уведомления | После запроса |
| Скачивание архива | Когда файл ещё не получен |
| Распаковка | После файла |
| Статические проверки | После распаковки |
| Решение по ИИ | Только если в статике есть `failed` |
| Стенд | На ветке, где просмотр поднимается |
| ИИ | После статики, по правилу развилки |
| Lighthouse | По временному просмотру. Не ждёт окончания ИИ и не заменяет его |
| Отчёт | Когда страница отчёта собрана |

ИИ и Lighthouse могут идти одновременно. Не рисовать замок «сначала Lighthouse, потом ИИ».

Ошибка: имя шага и текст «Ошибка этой части». Общего креста на весь ленд нет.

Замена своего ленда: «Предыдущий просмотр этого пользователя заменён.» Про чужой просмотр ничего не писать.

Что делать со стендом и Lighthouse, если человек отказался от ИИ, исходное ТЗ не сводит в одну фразу. На макете отказа эти два шага не рисовать уже запущенными. Вопрос открыт, см. конец документа.

## 5. Развилка после статики

Условие экрана: в статике есть хотя бы один `failed`.

Человек видит статический результат и два действия:

- «Разрешить ИИ»
- «Не разрешать ИИ»

`warning` этот экран не открывает. Если `failed` нет, ИИ начинается без вопроса. Отдельный мастер «продолжить?» не рисовать.

Если пункт «Проверка структуры» в статусе `failed`, в блоке статики только он и те пункты, которые система реально вернула. Остальной список раздела статики не заполнять серыми провалами.

Находка статики на этом экране: имя пункта, статус, текст находки, путь к файлу, если он есть. Пути нет — строку пути не выдумывать.

## 6. Отчёт

Одна страница. Три блока по порядку:

1. Статика
2. ИИ
3. Lighthouse

Шапку страницы собери из контекста: название, `human_id`, страны, языки, тип, статус каталога. Общего бейджа страницы нет. Трёхцветной «итоговой» плашки нет.

Над блоками одна строка: «Отчёт рекомендательный. Решение принимаете вы.»

Статусы частей независимы. Рисуй статус у каждого блока, не сумму.

| Часть | Что писать в статусе блока |
|-------|----------------------------|
| Статика | Сводка: «есть failed», «только warning» или «все passed». Отдельно: «проверка не завершилась», если прогон статики сломался |
| ИИ | «Список готов», «не запускался (ждут решения пользователя)» или «ошибка после повторов» |
| Lighthouse | «Выполнен» или «ошибка прогона» |

Статус Lighthouse — про прогон, не про оценку ленда. Слова «пройдено» и «не пройдено» по баллу не использовать.

Ошибка ИИ не прячет статику. Ошибка Lighthouse не прячет статику и ИИ.

### Блок «Статика»

Пункты, которые запустились. Имена:

| Пункт |
|-------|
| Проверка структуры |
| Проверка отсутствия PHP |
| Проверка размеров изображений |
| Проверка подключенных файлов |
| Проверка внешних ссылок |
| Проверка дат в индексе |
| Проверка UTF-8 meta-тега |
| Проверка фавикона |
| Проверка запрещённых файлов стиллера |
| Проверка тега `<style>` |
| Проверка устаревших макросов |
| Проверка макросов трекинга и формы |
| Проверка макросов tracker_protection |
| Проверка защитного скрипта в SVG |
| Проверка cache-buster `?v` |
| Проверка больших скриптов в HTML/PHP |
| Проверка размеров CSS |
| Проверка запрещённых элементов |
| Проверка base64 и atob |
| Проверка префикса `{{cdn}}/` в CSS/JS |

У каждого пункта: имя, `passed` / `warning` / `failed`, текст находки, путь к файлу, если он есть.

Пороги в этом блоке не пересказывать заново и не превращать в вердикт ленда. Числа живут в конфиге ТЛ.

### Блок «ИИ»

Список дефектов. У находки на макете всегда три части: путь к файлу, цитата, скриншот. Находки без любой из трёх на экране нет. Не рисовать карточку «дефект без доказательства» даже серой.

ИИ не ставит общий статус и не показывает кнопку «заблокировать ленд».

Пустой список при статусе «Список готов» возможен: дефектов с полным доказательством нет. Это не бейдж «годен».

Цитату показывать на языке ленда.

Что ИИ ищет, чтобы не придумать лишние секции блока: орфография; смешение языков; смысл фраз; личные имена, нетипичные для ГЕО; валюта, не соответствующая ГЕО; повтор картинки там, где макет требует уникальное изображение. Отдельные вкладки под каждый тип не обязательны. Один список находок.

### Блок «Lighthouse»

Две колонки: mobile и desktop. В каждой только performance-метрики:

| Метрика |
|---------|
| performance score |
| First Contentful Paint |
| Largest Contentful Paint |
| Total Blocking Time |
| Cumulative Layout Shift |
| Speed Index |
| Time to Interactive |

Шкалы «хорошо / плохо», порога балла и категории accessibility нет.

Подпись блока при успехе: «Выполнен». При сбое прогона: «Ошибка прогона».

Временный и подписанный URL в этот блок и вообще в постоянный отчёт не класть.

## 7. Сравнение

Текущий отчёт и прошлый отчёт того же `human_id` рядом. У каждого своя дата. У каждого те же три блока и те же правила статусов.

Не рисовать: «стало лучше», «стало хуже», «регресс», общий вердикт сравнения, дифф «годен относительно прошлого».

Если прошлого отчёта нет, второй колонки нет. Текст: «Прошлого отчёта этого human_id нет.»

QA открывает прошлый среди своих. Чужой прошлый отчёт в его сравнении не показывать. ТЛ может открыть отчёт любого пользователя; прошлый всё равно ищется по тому же `human_id`.

## 8. Стенд

Отдельный просмотр, не третья колонка отчёта.

Если среда выдала временный URL, показать его и сам просмотр. Подпись: «Временный адрес. В отчёт он не сохраняется.»

Пока разрешения нет, на экране явно: «Ленд сам ничего не выполняет: нет отправки лидов и нет сторонних пикселей.»

Кнопка: «Разрешить действия ленда». Это явное действие на этом просмотре. Исходное ТЗ называет его действием QA. Может ли ту же кнопку нажать ТЛ на своём просмотре, в ТЗ не сказано. На макете QA кнопка есть. На макете ТЛ ту же кнопку пометить как открытый вопрос, не прятать молча и не объявлять запретом.

Макросы, которые просмотр подставляет, в интерфейсе отдельным редактором не рисовать. Человек смотрит уже подставленную страницу. Другие макросы подставлять на макете «как будто работают» не нужно.

Подписанный URL файла из AIO на стенде не показывать.

## 9. Списки отчётов

Дата отчёта видна. Срок 3 месяца в интерфейсе как таймер не рисовать: это удаление на стороне системы.

| | QA | ТЛ |
|---|----|----|
| Чьи строки | Только свои | Все |
| Колонки, которых хватает | Дата, `human_id`, название, статус статики, статус ИИ, статус Lighthouse | Те же плюс кто запустил |
| Чего нет в строке | Общий вердикт, затраты, чужие отчёты | Общий вердикт |

Переключатель пользователя у QA не рисовать.

## 10. Затраты, только ТЛ

Экран чисел из ответа провайдера модели. Подписей своего тарифа, рублей «по прайсу» и прогноза нет: прайс в ТЗ не задан.

Два состояния:

- цифры есть — показать то, что вернул провайдер, без пересчёта в другую валюту;
- учёта нет — текст: «Провайдер модели не вернул учёт использования.»

QA этот экран не видит: ни пункта меню, ни урезанной версии.

## 11. Админ-конфиг, только ТЛ

Одна страница текущих значений. Истории, диффа версий и кнопки «откатить» нет.

Новую проверку и новое число «добавить правило» не рисовать. Меняются только уже существующие параметры.

| Поле на экране | Стартовое содержимое, которое можно подписать |
|----------------|-----------------------------------------------|
| Разрешённые внешние префиксы | Список ниже |
| Запрещённые макросы | То, что раздел статики называет явно. Условные правила формы не сводить в один плоский запрет: рядом флаг `expectFormMacro` |
| Запрещённые скриптовые признаки | То, что названо явно: элементы `object`, `iframe`, `form`; встроенный `<script>` без `class`, содержащего `whitelist`, длиннее 10 непустых строк. Остальное в модулях дословно не раскрыто — пустые выдуманные строки не добавлять |
| Порог изображений | Больше 100 KB и не больше 200 KB — `warning`. Больше 200 KB — `failed` |
| Порог CSS | До 50 KB — норма. От 50 KB до 150 KB включительно — `warning`. Больше 150 KB — `failed` |
| Порог встроенного скрипта | Больше 10 непустых строк — `failed`, с исключением `whitelist` в `class` |
| `expectFormMacro` | Включён (`true`). Не вычислять его из типа ленда на экране |
| Ожидаемые языки поверх метаданных ленда | Пусто значит «брать языки ленда». Замена это или дополнение — открытый вопрос. Подпись поля не должна выбирать одно из двух |

Стартовые разрешённые префиксы:

- `http://www.w3.org/2000/svg`
- `http://www.w3.org/1999/xlink`
- `https://fonts.googleapis.com`
- `https://fonts.gstatic.com`
- `https://code.jquery.com`
- `https://ajax.googleapis.com`
- `https://cdn.jsdelivr.net`
- `https://scripts.converteai.net`
- `https://images.converteai.net`

Кнопка сохранения есть. Ленты аудита нет.

## 12. Пользователи, только ТЛ

Пункт меню «Пользователи» есть у ТЛ. У QA этого пункта нет.

Список: логин и роль. Пароля и хеша в списке нет. Учётку, заданную окружением, пометить текстом «Задана окружением», без пароля.

Форма создания: логин, пароль, роль. Роль на форме — ТЛ или QA. Кнопка создания есть.

Логин, который уже есть, включая логин ТЛ из окружения: «Такой логин уже есть.» Пароль после создания в списке не показывать.

Восстановление пароля не рисовать. Кнопок удаления и редактирования пользователя нет.

## Что не рисовать

- Общий вердикт страницы, проверки или сравнения.
- Порог балла Lighthouse и вердикт «пройдено / не пройдено» по метрике.
- Затраты, конфиг, чужие отчёты и пункт «Пользователи» у QA.
- Восстановление пароля и самостоятельная смена пароля.
- Пароль и хеш в списке пользователей.
- Удаление и редактирование пользователей.
- История конфига.
- Jira, Telegram, почта, выгрузка в таблицы.
- Вход в AIO и поле токена.
- Выбор между `merged` и `original`.
- Пустые пункты статики, которых не было в прогоне.
- Находку ИИ без пути, цитаты или скриншота.
- Подписанный URL и токен в постоянном отчёте.
- `preview_image` вместо скриншота стенда.
- Суточный лимит проверок.
- Золотой набор лендов и экран эталонов.
- Новый бренд.

## Вне объёма

Вёрстка, компоненты Angular, цвета бренда, внутренний API, хранение, повторы на сервере, тексты модулей SpyOwl сверх имён пунктов и полей конфига.

Пункты изоляции стенда из файла ориентира не превращать в отдельные строки статического отчёта.

## Открытые вопросы

Исходное ТЗ их не закрывает. В макетах не выбирать ответ молча.

| Вопрос | Как держать в макете |
|--------|----------------------|
| Стенд и Lighthouse после отказа от ИИ | На ветке отказа не показаны как уже идущие |
| Кнопка разрешения действий стенда у роли ТЛ | У QA есть. У ТЛ помечена как вопрос |
| Отдельный статус «пользователь отказался от ИИ» | В разделе статусов его нет. Кнопка отказа есть. Не вешать на отказ бейдж «годен» |
| Языки в конфиге: замена или дополнение | Поле есть, формулировка не выбирает режим |
| Полные списки признаков «как в модуле» | Не дописывать выдуманными строками |
| Свой вид, если среда не выдала временный URL | Не подставлять постоянную ссылку в отчёт |
| Живёт ли стенд после готового отчёта | URL в постоянный отчёт не класть |
| Схема цифр провайдера | Экран показывает пришедшие цифры или «учёта нет» |
| Пороги Lighthouse | Не заданы и в MVP не вводятся |

Закрыто исходным ТЗ и в макетах уже учтено: каталог последних 300 таблицей из трёх колонок, поиск по таблице, кнопка «Обновить», выбор строки, остановка текстового запуска при коллизии, файл `original`, отсутствие общего вердикта, доказательства ИИ из трёх частей, поля входа «Логин» и «Пароль», ошибка «Неверный логин или пароль.».

## Критерии приёмки

Принимает заказчик. Золотого набора лендов нет. Пороги баллов Lighthouse в приёмку не входят. Ниже критерии раздела 14 исходного ТЗ в части экранов.

| # | Готово, если |
|---|----------------|
| 1 | Есть вход ТЛ и QA. У QA нет чужих отчётов, затрат и конфига. У ТЛ есть все отчёты и экран затрат, включая состояние «учёта нет». QA не создаёт пользователей и пункта меню нет. ТЛ из окружения входит и может создать пользователя с ролью |
| 2 | Есть таблица с колонками «id», «Лендинг», «Создано» (больший id сверху), поле «Поиск», кнопка «Обновить», выбор строки и карточка до скачивания. Пустая таблица и пустой поиск — разные тексты. Текст «не среди последних 300» без скачивания. Коллизия текстового запуска без скачивания; выбранная строка запускается |
| 3 | При битой структуре остальных пунктов статики нет. Есть явное «Разрешить ИИ» и «Не разрешать ИИ». Сам ИИ в этой ветке не выглядит уже запущенным |
| 4 | Без `failed` вопроса про ИИ нет. В блоке ИИ у находки путь, цитата и скриншот. Общего статуса нет |
| 5 | Есть экран стенда с временным URL и явным разрешением действий. До разрешения на макете нет самостоятельной отправки лида и сторонних пикселей |
| 6 | Видно, что новый запуск заменяет предыдущий просмотр этого пользователя и не трогает чужой |
| 7 | Lighthouse показывает mobile и desktop без вердикта по баллу. Ошибка прогона не убирает блок статики |
| 8 | Ошибка ИИ оставляет блок статики на месте |
| 9 | Интерфейс и отчёт по-русски. Прошлый отчёт того же `human_id` рядом с текущим. Общего статуса страницы и сравнения нет. Дата отчёта есть |
| 10 | В постоянном отчёте нет токена и подписанного URL |
| 11 | Кнопка «Обновить» на экране запуска и не спрятана за ожидание 10 минут |
