# Backend MVP — внутренний помощник QA

NestJS сервис. Продуктовые данные — Neon (serverless Postgres) по `DATABASE_URL`. Распакованные ленды и zip — файлы в `WORK_DIR`, не строки Postgres.

## Запуск

```bash
cd backend
npm install
copy .env.example .env
```

Заполните `.env` локально. В репозиторий не кладите настоящие `AIO_TOKEN`, `TL_LOGIN`, `TL_PASSWORD`, пароли и подписанные URL.

```bash
npm test
npm run build
npm start
```

`npm test` не ходит в Neon и в AIO: репозитории в памяти, клиент AIO подменён.

При `npm start` и `STORAGE=neon` схема создаётся сама (`CREATE TABLE IF NOT EXISTS`). Отдельная команда миграций не нужна.

## Переменные

Смотрите `.env.example`. Обязательны `DATABASE_URL` (для neon), `AIO_TOKEN`, `TL_LOGIN`, `TL_PASSWORD`.

Первый тимлид только из окружения. Его пароль в таблицу `users` не пишется. Остальных создаёт тимлид: `POST /admin/users` с `login`, `password`, `role` (`ТЛ` или `QA`). В базе хеш bcrypt.

## Сессия

`POST /session` `{ "login", "password" }`. Сначала пара `TL_LOGIN` / `TL_PASSWORD` (роль `ТЛ`), иначе пользователь из Neon. Чужой логин или пароль — один и тот же ответ `401` `{ "error": "Отказ во входе" }`.

Идентификатор сессии: JSON `session_id` и cookie `qa_session` (HttpOnly). Дальше заголовок `x-session-id`, `Authorization: Bearer` или cookie. `DELETE /session` завершает сессию. Сессии живут в памяти процесса.

Саморегистрации, смены и сброса пароля, правки и удаления пользователей нет.

## Каталог и проверка

`GET /catalog` читает кэш и сортирует `human_id` как число по убыванию. В AIO сам не ходит.

Фон: при `CATALOG_AUTO_REFRESH=1` тот же запрос списка выполняется на старте и каждые 10 минут. `POST /catalog/refresh` выполняет его сразу.

`POST /checks` с одним `human_id` ищет точную строку. Промах — одно обновление каталога и повтор. Нет строки или несколько строк — скачивание не начинается. Коллизия отдаёт карточки без выбора победителя. Пара `human_id` + `uuid` берёт эту строку даже при повторе `human_id`; промах пары скачивание не начинает и каталог заново не тянет.

Дальше: `Download Requested`, уведомление `lander.download` / `done` / тот же `lander_uuid`, файл `kind=original`. `merged` не скачивается. Ответ `process` отчётом не считается.

У пользователя один каталог в `WORK_DIR/users/<sha256 логина>/current`. Новый запуск удаляет предыдущий каталог только этого пользователя. После отчёта файлы остаются до следующего запуска того же пользователя, чтобы временный просмотр ещё открывался. В Postgres их нет.

Токен AIO — только query-параметр `token`. Cookie, `Authorization` и `x-tenant-id` на вызовы AIO не ставятся. Токен, подписанные URL и `preview_image` в постоянный отчёт и в логи не пишутся.

## Отчёт

Три блока: статика, ИИ, Lighthouse. Общего вердикта нет. Тексты системы по-русски. Запись живёт 3 месяца. `GET /reports/{id}/previous` отдаёт прошлый отчёт того же `human_id` в пределах доступа или `{ "report": null }`. Вердикт сравнения не считается.

QA видит только свои отчёты. Чужой отчёт, конфиг, затраты и методы пользователей — отказ `403`, не пустые данные.

## Стенд

`GET /preview/{check_id}/...` подставляет `{{form}}`, `{{aio.visit.fields.offer_name.for_visitors}}` и `{{cdn}}`, выставляет `window.__CDN_BASE__`. Другие макросы не трогает. До `POST /checks/{id}/stand-actions` `{ "decision": "allow" }` включены изоляция разметки и CSP: внешние скрипты снимаются, у формы нет отправки, `connect-src 'none'`. Разрешение доступно владельцу просмотра (и QA, и ТЛ на своей проверке).

`stand_url` есть только в `GET /checks/{id}`, пока каталог на диске. В объект отчёта он не пишется.

## Что сознательно не живое в этой среде

| Часть | Как устроено |
| --- | --- |
| AIO, Neon | Реальный клиент и репозиторий Postgres есть. Тесты подменяют их. |
| Подключённые файлы | Правило как в aio-checker (link/script, файл на диске). Запуск Puppeteer не требуется: теги читаются из файла. Узлы, которые появляются только после JS в браузере, этот разбор не видит. |
| Скриншот для ИИ | Браузер не запускается, кадр стенда не снимается. Находка без пути, цитаты и скриншота в блок не попадает. `AI_MODE=stub` ничего не вызывает. `AI_MODE=real` вызывает Google Gemini `generateContent` (модель по умолчанию `gemini-3.5-flash-lite`; в ТЗ раньше фигурировал Qwen) и забирает `usageMetadata` как есть, без своего тарифа. Ключ: `GEMINI_API_KEY` или `AI_API_KEY`. |
| Lighthouse | `LIGHTHOUSE_MODE=stub` отдаёт сводку mobile и desktop без порога «пройдено». `real` запускает CLI, категория только `performance`. |
| Опрос уведомлений | В ТЗ период не задан. Одна попытка — `AIO_NOTIFY_POLLS_PER_ATTEMPT` опросов с паузой `AIO_NOTIFY_POLL_MS`. У части 3 попытки. |
| `languages_override` | Непустой список заменяет языки карточки. Пустой — остаются языки ленда. |
| Отказ от ИИ | Стенд и Lighthouse после `deny` не запускаются. Статус блока ИИ остаётся «не запускался (ждут решения пользователя)», решение `deny` лежит отдельно в `decision`. |
| Чужая незавершённая проверка | Её видит только владелец, в том числе если смотрит тимлид. |

Значения `form.html`, `brand_name` и базы CDN задаются `STAND_FORM_HTML`, `STAND_BRAND_NAME`, `STAND_CDN_BASE`.
